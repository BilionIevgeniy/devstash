# 11. English and German (i18n)

## Why

- DevStash targets developers in Germany, and the legal pages (feature 2) are in German anyway. Users should be able to switch the interface between English and German.
- Interview angle: "How does i18n work with Server Components?", "Locale in the URL or in a cookie: trade-offs?", "How do you format dates and numbers for `de-DE`?"

## Decisions (cross-file decision 1 in `README.md`; record them in ADRs)

- **Library: next-intl** (Server and Client Components, documented setup without i18n routing). Verify against the installed version
- **Public pages stay static.** The root layout never reads cookies or headers. The marketing page exists as `/` (English) and `/de` (German): two static pages rendering the same components with an explicit locale. Legal pages are bilingual on one static page (feature 2)
- **Auth pages and the app** take the locale from a cookie that is set only when the user picks a language; without it from `Accept-Language`; default English. No locale prefix in their URLs: a `[locale]` segment would move every route (including the intercepting drawer and the auth pages) and force composing the next-intl proxy with the Auth.js proxy
- `<html lang="en">` stays in the root layout; content in German sets `lang="de"` on its top wrapper element
- **next-intl is a vendor library used outside `lib/`** (components and pages call its hooks). ADR: an exception to the vendor rule, and `src/i18n/` (config and messages only) added to the Layout in `architecture-rules.md`
- **The language switch** (a Server Action that sets the cookie, then `refresh()`) lives in `app-shell` (the plan review may choose a new `i18n` module with its own `FEATURE_RANKS` row instead)
- The language cookie is a preference set on an explicit user action; list it in the privacy notice (feature 2)

## Scope

0. **Step 0, its own PR: error codes.** Services and Server Actions return error **codes**, not English sentences (a change to `OperationResult`/`ActionResult` in `lib/action-result.ts`, with an ADR); components map codes to messages. Zod schemas return codes as messages; `domain/` stays pure (keys, no next-intl import)
1. Setup: `src/i18n/request.ts` (`getRequestConfig` reading the cookie, then the header), `messages/en.json` and `messages/de.json`, the next-intl plugin in `next.config.ts`, the client provider where client components need messages
2. **Strings, in this order** (each step mergeable alone):
   1. marketing page (`/` and `/de`) and footer
   2. auth pages and emails (Resend templates per locale)
   3. app shell: sidebar, top bar, menus, empty states, toasts
   4. item and collection screens, settings, billing
3. **Language switch** in the user menu (app) and links between `/` and `/de` (marketing)
4. **Formatting**: dates, relative times and numbers through next-intl's formatters (`Intl` underneath), with the user's locale and `Europe/Berlin` as the default time zone
5. Type-safe keys (next-intl TypeScript augmentation) so a missing key fails `tsc`
6. **Guard against new literal strings**: an ESLint rule for literal strings in JSX (for example `eslint-plugin-i18next` `no-literal-string` on `src/**/*.tsx`, excluding `components/ui` and tests); check the plugin supports ESLint 9 flat config, otherwise pick an equivalent and name it in the plan

## Non-goals

More languages, translated user content, localized URL paths for the app, translating AI output.

## Acceptance criteria

- `/` and `/de` are static pages (build output) with the full marketing page in each language
- Switching the language changes every app and auth screen, email and error message; the choice survives sign-out and sign-in
- The literal-string lint rule passes; no hard-coded user-facing English string remains in `src/`
- Dates show as `10.11.2026` / `vor 2 Stunden` in German and `11/10/2026` / `2 hours ago` in English
- Build, tests and the E2E smoke suite (feature 5) stay green

## Tests

Unit: locale resolution (cookie > header > default). RTL: a component renders German strings with the provider. E2E: switch to German, reload, still German; `/de` renders German without a cookie.
