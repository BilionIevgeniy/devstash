# 24. Functions and database closer to the users

## Why

- Found in feature 22 (`docs/performance.md`, "Production"): the functions run in Vercel's default `iad1` and Neon in `us-east-2`, while the users are in Germany. Every request that reaches a function pays the Atlantic once (`fra1::iad1` in `x-vercel-id`, about 100 ms) before any database read, and every app page is dynamic (ADR 0037)
- Moving only the functions to `fra1` would put the Atlantic between the function and the database instead, once per query: worse
- `src/proxy.ts` and the static shells already answer from `fra1`, so neither shortens this path. Measured from Germany on 2026-11-25: `/sign-in` (HIT) 70–125 ms, the signed-out redirect of `/dashboard` 85–105 ms, `/api/auth/session` (function in `iad1`, no database read) 180–215 ms, cold start 1.9 s

## Decided (owner, 2026-11-25)

- The move is made: Neon in `aws-eu-central-1` and `regions: ["fra1"]` in `vercel.json`, together
- A Neon project's region is fixed at creation and a branch cannot be in another region, so it is a new project. The owner created it: `devstash-eu`, `lively-wildflower-46234559`, Frankfurt, Free plan, Postgres 18.7 like the old one
  - `production`: `ep-green-mud-bhzhz461.c-10.eu-central-1.aws.neon.tech`
  - `development`: `br-raspy-sound-bh0suynz`, `ep-soft-art-bhqrx5ln.c-10.eu-central-1.aws.neon.tech`
- Upstash (`devstash-ratelimit`) is already in AWS `eu-central-1`: nothing to move, its region goes into the processing record
- Neon's production statistics are not read: with the decision made, the numbers from outside before and after are enough
- No connection string and no password enters the conversation: the owner runs the copy and sets the variables

## Scope

1. The numbers before the move, from outside, in `docs/performance.md`
2. An ADR with the decision, the order of the move and the rollback
3. `regions: ["fra1"]` in `vercel.json`
4. Every place that names the old project: `scripts/neon-endpoints.ts`, the tests of the two guards, the Neon ids in `CLAUDE.md`, the regions in the privacy notice (both languages) and in `docs/privacy/processing-record.md`
5. A copy of both databases (about 9 MB for development, extension `pg_trgm`, `pg_dump` of Postgres 18 through Docker), rehearsed on `development`, checked by comparing the two sides
6. The write freeze during the production copy: there is no such mode today, so the plan chooses one
7. The preview environment follows production's region: its variables point at the new `development` before the PR is pushed, or the migration guard refuses its build
8. The numbers after the move

## Non-goals

Multi-region, a read replica, an edge runtime.

## Acceptance criteria

- Production answers from `fra1` functions (`x-vercel-id`) and the new project, with every row of the old one
- Before and after numbers in `docs/performance.md`
- No place in the code, the docs or the legal texts names the old region as the current one
- The rollback is written down, and the old project stays until the owner deletes it
