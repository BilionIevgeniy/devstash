# 16. Codebase hygiene

## Why

- The code style is not in sync with the editor. The editor formats on save with Prettier's defaults, but the repository says nothing about what "formatted" means: no `.prettierrc`, no `.prettierignore`, no `format` script, no check in CI, no `.vscode/settings.json`. 83 tracked files differed from Prettier's output on 2026-11-12 (17 shadcn files in `src/components/ui` without semicolons, 22 other files in `src`, `eslint.config.mjs`, `scripts/test-db.ts`, and Markdown in `context/`, `docs/`, `.claude/`, `README.md`). A save rewrites a whole file, so a one-line change shows as dozens.
- CI builds without the Next.js build cache: every run of `ci` and `e2e` compiles from scratch, and a PR waits 4–6 minutes.
- CI does not catch a change of `schema.prisma` without its migration: CI and the Vercel build pass, `migrate deploy` applies nothing, production fails on the missing column (ADR 0013, "Not covered yet").
- `prisma/seed-data.ts` is behind the demo migration `20261030120000_demo_items_content`: a fresh database gets the old placeholders.
- Some folders are hard to scan: `src/lib` (28 files without tests), `items/_internal/components` (36), `app/(marketing)/_components` (26), `items/components` (19), `items/domain` (15), `components/common` (15). And `npm run lint:dup` found copies worth one home.
- Interview angle: "How do you keep a codebase consistent as it grows?", "How do you refactor structure without changing behaviour?"

## When

With no other branch open: the sweep and the moves conflict with everything. Behaviour does not change anywhere in this feature.

## Scope (one commit each, in this order)

1. **The style, committed**: `.prettierrc` (what the editor uses today, the defaults), `.prettierignore` (`src/generated`, `prisma/migrations`, `public/monaco`, `.next`, the lockfile; decide whether Markdown is in: Prettier re-aligns every table, so the course specs in `context/features/` may go to the ignore list), `.vscode/settings.json` (`editor.formatOnSave`, `editor.defaultFormatter: esbenp.prettier-vscode`, `prettier.requireConfig`)
2. **The sweep**, its own commit: `prettier --write` over everything, so the diff is whitespace and punctuation only; review with `git diff -w`. Its hash goes into `.git-blame-ignore-revs`, with a comment that the hash survives because PRs are merged with `--merge` (a squash or rebase merge would change it)
3. **The check**: `npm run format` and `format:check`, `format:check` in the `ci` job (already a required check), the command in `CLAUDE.md` and in "Testing" in `coding-standards.md`; after `npx shadcn add`, `prettier --write` on the new file. The working rule "format only the files you touched" ends here, and the line in `coding-standards.md` ("Styling") that points at the style item changes with it
4. **The build cache in CI**: an `actions/cache` step for `.next/cache` in `.github/workflows/ci.yml`, in the `ci` job before `npm run build` and in the `e2e` job before Playwright starts the build. Key: the hash of `package-lock.json` and of the sources, with a `restore-keys` fallback on the lockfile hash, as in the Next.js docs on CI build caching (`node_modules/next/dist/docs/` first). Confirm the "no build cache" warning is gone from the second run's log
5. **Schema without its migration fails CI**: a step in the `integration` job (the only one with a Postgres service besides `e2e`) that compares the migrations with `schema.prisma` and exits non-zero on a difference. Prisma 7 has no shadow database in `prisma.config.ts`: settle the flags with `npx prisma migrate diff --help` on the installed CLI and its docs, not the todo's old command. Prove it once with a deliberate schema edit on the branch, then revert. ADR 0013's "Not covered yet" gets an addendum (a new record), not an edit
6. **The seed**: copy the content of the demo migration into `seed-data.ts`, or let the seed create only the user and leave the content to the migration. Keep the deliberate development state: the demo user on the Free plan with 49 items and 2 collections, one short of both limits. The README section on seeding says that the seed differs from production on purpose (the production demo user stays Pro with the content of the migrations) and that collection pagination cannot be checked with it
7. **Topic subfolders**, one commit per folder, no `index.ts` (barrels stay banned, ADR 0015): `git mv` with the colocated tests, then the imports in `src/`, `test/`, `e2e/`, the `vi.mock` paths and the Storybook stories. Grouping idea, judged again at the plan:
   - `lib/`: `errors/` (action-result, error-summary, error-text, navigation-error, route-error, validation), `http/` (api-response, client-ip, app-url, legal-paths), `observability/` (logger, sentry, sentry-server, sentry-scrub), `i18n/` (i18n-request, locale-cookie), `db/` (prisma, advisory-lock, full-text-search, order-by-ids, pagination), `vendors/` (email, openai, r2, rate-limit, stripe); `utils.ts` and `hash.ts` stay at the root
   - `items/_internal/components/`: `drawer/`, `form/`, `delete/`, `locked/`, `toggles/`, `fetch/`; `items/components/`: `lists/`, `drawer/`; `items/domain/`: `list/`
   - `app/(marketing)/_components/`: `sections/`, `chaos/`, `legal/`; `components/common/`: `providers/`, `lists/`
   - the exact paths in `eslint.config.mjs` (`lib/validation.ts`, `lib/logger.ts`, `lib/utils`, `LegalPage.tsx`, `BilingualErrorText.tsx`), the `@/lib/sentry` alias in `vitest.shared.mts`, the Storybook config if it names paths
   - a rule in `architecture-rules.md`: "a folder past about 12 files is split by topic, without `index.ts`"
8. **The copies jscpd found** (judge each with the `code-reviewer` first): `ConfirmEmailForm` and `ResetPasswordForm` share about 48 lines (the password fields with their confirmation, the submit and its error), a candidate for one `PasswordFields` in `auth/_internal/components/`; `StatsCards` (dashboard) and `UsageStats` (profile) render the same counts, a candidate for one component composed by both routes. The other clones are parallel on purpose (the create dialogs' Radix markup, the thin entry points, two skeletons)

## Non-goals

ESLint 10 (a Watch item in `context/todo-before-live.md`, waiting for its plugins), any behaviour or UI change, renaming exports.

## Acceptance criteria

- `npm run format:check` passes and runs in `ci`; a file saved in the editor shows no unrelated diff
- The second CI run uses the build cache
- A schema edit without a migration fails the `integration` job
- `npm run lint`, typecheck, the tests, the build, integration and e2e are unchanged and green after every commit; the sweep changes only whitespace and punctuation: `git diff -w --word-diff=porcelain` shows nothing but `;`, quotes, commas and parentheses in code, and the Markdown diff is read in full

## Tests

No new tests apart from the moved ones; the deliberate schema edit of item 5 is the proof of the check.
