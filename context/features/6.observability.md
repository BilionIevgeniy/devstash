# 6. Observability

## Why

- Errors in production today go only to `console.error` (Vercel logs, short retention) or to the browser console (`app/(app)/error.tsx`). A failed Stripe webhook or AI stream leaves no record anyone looks at.
- Interview angle: "Where do you see a production error at 3 a.m.?", "How do you connect the error a user sees with the server log?"

## Scope

1. **`src/instrumentation.ts`** with `register()` and `onRequestError` (Next.js instrumentation hook), and `src/instrumentation-client.ts` if the chosen SDK needs it. Check both file conventions in the installed Next docs
2. **Sentry** (`@sentry/nextjs`, pinned), or a documented alternative chosen in the plan review:
   - organization in the **EU data region**
   - keep `sendDefaultPii` off (the default), no Session Replay, no user email or content in events; only the user id (cuid)
   - source maps uploaded in the Vercel build, not served publicly
   - the SDK is a vendor: add `@sentry` to the `VENDOR_SDKS` pattern in `eslint.config.mjs`; code imports it through `lib/` only; `src/instrumentation.ts`, `src/instrumentation-client.ts` and `next.config.ts` (`withSentryConfig`) are the documented exceptions, recorded in an ADR
3. **Error boundaries report**: the three boundaries `src/app/error.tsx`, `src/app/(app)/error.tsx` and `src/app/global-error.tsx` send client-side errors with their `digest`. Server errors are already captured by `onRequestError`, so the client side must not report the same error twice (deduplicate by digest)
4. **Structured logs and caught errors**: `onRequestError` only sees uncaught errors; the Stripe webhook and the AI routes catch theirs. A tiny `lib/logger.ts` (level, message, ids) replaces bare `console.error`, and its `error()` also calls `Sentry.captureException`, so caught failures reach Sentry too
5. **Privacy**: add Sentry to `docs/privacy/processing-record.md` and the privacy notice (feature 2); no cookies or Replay, so §25 TDDDG consent stays unnecessary
6. **Alert**: one email alert for new issues in production

## Non-goals

Tracing dashboards, performance monitoring beyond the defaults, log shipping to another vendor.

## Acceptance criteria

- A thrown error in a Server Component, a Route Handler and a Server Action each appears in Sentry with route, digest and no PII
- A failed Stripe webhook appears as an event
- Local development without a Sentry DSN works (the SDK stays off)
