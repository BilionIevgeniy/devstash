# 24. Functions and database closer to the users

## Why

- Found in feature 22 (`docs/performance.md`, "Production"): the functions run in Vercel's default `iad1` and Neon in `us-east-2`, while the users are in Germany. Every dynamic page pays the Atlantic once (`fra1::iad1` in `x-vercel-id`, about 100 ms of a TTFB of about 245 ms) before any database read, and every app page is dynamic (ADR 0037)
- Moving only the functions to `fra1` would put the Atlantic between the function and the database instead, once per query: worse

## Scope

1. Measure first: the database latency inside the region from Neon's query statistics of the production branch (read only with the owner's explicit go), and the production TTFB of a signed-in page
2. Decide with the numbers, in an ADR: Neon in `aws-eu-central-1` and `regions: ["fra1"]` in `vercel.json` together, or stay. A move is a new Neon project or branch in the EU region and a data migration with a short write freeze (expand/contract does not apply to a region); the processing record and the privacy notice name the new regions
3. The preview environment follows production's region, so preview numbers stay comparable

## Non-goals

Multi-region, a read replica, an edge runtime.

## Acceptance criteria

- Before and after numbers in `docs/performance.md`, or the decision to stay with its numbers in the ADR
