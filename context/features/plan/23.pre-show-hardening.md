# 23. Pre-show hardening

## Why

- A full review on 2026-11-24 by three agents (`architecture-reviewer`, `code-reviewer` over all of `src/`, a senior frontend review from a German hiring panel's view) found nothing critical: lint and types clean, 0.49 % clones, every Server Action checks the session. All three agree the project can be shown once the findings below are done.
- The riskiest server paths have no test of their own and are mocked everywhere else, so a regression (a fail-open rate limiter, an enumerating reset) would pass CI. Both code reviews found the same files independently.
- `items` and `collections` keep reads in four places (`queries.ts`, `queries/`, `_internal/queries.ts`, `_internal/queries/`) with no rule for where a new read goes; ADR 0017 allowed the mix "while only part of the reads has moved" and never ended it.
- The static homepage hides its calls to action until the session answer comes, which looks like a slow connection.
- Interview angle: "How do you refactor safely?" (tests first), "Why queries and services and not mutations?" (CQS on the server, ADR 0009/0017), "Why not redirect signed-in users from `/`?" (below).

## Settled in the review (not reopened)

- **No `mutations` files.** The query/mutation split of RTK Query exists for the client cache (cached and subscribed vs. tag invalidation). On the server the same idea is command–query separation, which the project already has: `queries` only read (lint, ADR 0009), `services/` write. Next.js describes the same split ("Data Access Layer", `node_modules/next/dist/docs/01-app/02-guides/data-security.md`).
- **Types stay where they are** ("Where types live" in `architecture-rules.md`): a type lives with the value it comes from (`02-project-structure.md`, "Colocation"). A `.types.ts` beside every file would double the files and split `Prisma.ItemGetPayload<typeof select>` from its select; one shared types folder is the god file ADR 0017 avoids. No `enum` exists; `as const` tuples and literal unions stay the rule.
- **Reads that sign R2 URLs or compose another feature's data stay in `services/`** (rule 5). The role table says so (step 8).
- **No redirect from `/` and `/de` for signed-in users.** The navbar of every marketing page (`/impressum`, `/datenschutz`, `/agb`, `/vertraege-kuendigen`) needs the session anyway; the proxy sees only the JWT, not a revoked session (`auth.config.ts` has no session-version check), so a password change on another device would bounce the visitor `/` → `/dashboard` → `/sign-in` and lock them out of the homepage; `/#pricing` links would break for signed-in users; every homepage view would run the proxy (`authentication.md`, "Optimistic checks with Proxy").
- **No hint cookie with an inline `<head>` script**: a non-essential cookie on a consent-managed page (§ 25 Abs. 2 Nr. 2 TDDDG covers only what is strictly necessary), a CSP hash to keep in sync (ADR 0036), and the hint can still be wrong.

## Scope

One branch, one PR, one commit per step, in this order: the tests land before the code they protect is refactored (Fowler, _Refactoring_, 2nd ed., ch. 4; Feathers, _Working Effectively with Legacy Code_), and the behaviour changes (6, 7) are commits of their own, apart from the refactors (2, 3).

1. **`test:` the test gaps.** Each file below gets its colocated test:
   - `src/lib/vendors/rate-limit.ts`: a `reason: "timeout"` of the library throws (fail closed), a short `RATE_LIMIT_HASH_KEY` throws, a request with no IP skips only the per-IP limit
   - `src/features/auth/services/password-reset.ts`: the same neutral answer for a known and an unknown address, the single use of a token (`count !== 1`), an expired token
   - `src/features/auth/services/registration.ts`: the unique-key race, the neutral answer
   - `src/features/auth/services/email-rate-limit.ts`, `src/features/auth/_internal/services/token-store.ts`: their own decisions, if not already pinned by `email-verification.test.ts`
   - `src/app/api/webhooks/stripe/route.ts`: 400 for a bad signature, 500 for a failed sync (Stripe retries only then)
   - `src/app/api/auth/register/route.ts`: 429 with `Retry-After`
   - `src/features/files/_internal/components/put-file.ts` and `hooks/use-file-upload.ts`: the attempt counter, the abort on reset and unmount, the navigation sentinel (`Promise.withResolvers()`)
   - The client side of `ai`: `use-ai-text-stream.ts`, `use-frame-text.ts`, `stream-ai-text.ts`, `use-prompt-accept.ts`, `use-tag-suggestions.ts`, `use-description-summary.ts` (unmount before the answer, a refused result, a redirect)
   - `src/features/account/_internal/services/remove-account.ts`, `src/features/items/domain/list/list-pages.ts`, `src/features/search/schemas.ts` (cursor bounds)
2. **`refactor:` the query split, file or folder.** A feature with a `queries/` folder has no `queries.ts`; a small feature keeps its one file (auth, billing, editor, item-types). Behaviour and exports stay; only paths change (about 20 import sites, the colocated tests move along).
   - `items/queries/`: `dashboard.ts` (`getPinnedItems`, `getRecentItems`, `getItemStats`, `getItemCount`), `sidebar.ts` (`getSidebarItems`), `type-page.ts` (`countItemsOfType`, `getItemsOfType`, `getTypeTagNames`), `edit-state.ts` (`getItemEditState`); `lists.ts`, `search.ts`, `import.ts` unchanged
   - `items/_internal/queries/`: `selects.ts` (the shared selects, mappers and orderings: `NEWEST_FIRST`, `PINNED_FIRST`, `cardItemSelect`, `toItemCardData`, `toTagFields`, `itemTagsSelect`; no reads), `item-detail.ts` (`getItemDetail`, `getItemDetailOfType`, `getItemFileKey`), `collection-records.ts`, `file-records.ts`; the rest unchanged
   - `collections/queries/`: `dashboard.ts`, `list.ts`, `sidebar.ts`, `favorites.ts`; `fetchCollections`, `typeRanker` and the selects to `_internal/queries/collection-rows.ts`
   - ADR 0017 gets a dated amendment: "a feature uses either the file or the folder", and `_internal/queries/selects.ts` holds shapes, not reads. `eslint.config.mjs` needs no change (it already covers both forms)

## Non-goals

A redirect of the homepage, a hint cookie, `mutations` files, a types file per source file, a `reconciledAt` migration, new features.

## Acceptance criteria

- Every file in step 1 has its test, and each new test fails when its rule is broken (checked once per file by hand, recorded in the PR)
- No feature has both `queries.ts` and `queries/`; `tsc` refuses an `enum`
- The item page makes one service call; no business `if` in it
- On `/` and `/de` every call to action has its final size from the first paint; no spinner on a fast answer; the mobile menu never shows "Sign in" to a signed-in user; the axe scans and the visual baselines pass unchanged
- The reconciliation reaches every row within a few runs at any volume (test)
- `npm run format:check`, `test`, `typecheck`, `lint`, `build`, `test:integration` and `test:e2e` green
