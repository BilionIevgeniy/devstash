# 1. CI and safe migrations

## Why

- `npm run build` runs `prisma migrate deploy` against `DIRECT_URL` (`package.json`, `prisma.config.ts`). Every Vercel build migrates a database, including preview builds of unmerged branches. If a preview's `DIRECT_URL` points at production, an unmerged migration changes the production schema.
- There is no CI: lint, type check and tests run only when someone remembers. `main` can go red without anyone noticing.
- Interview angle: "How do you keep `main` green?", "How do you deploy a schema change safely?", "What happens if the migration succeeds and the build fails?"

## Scope

1. **Scripts** in `package.json`:
   - `typecheck`: `next typegen && tsc --noEmit` (check the exact `next typegen` command against the installed Next docs)
   - `build`: `prisma generate && node scripts/copy-monaco.mjs && next build`, without `prisma migrate deploy`
   - `db:migrate:deploy`: `prisma migrate deploy`
2. **GitHub Actions** `.github/workflows/ci.yml`, on `pull_request` and on `push` to `main`:
   - Node from `.nvmrc`, `npm ci` with the npm cache
   - `npm run lint`, `npm run typecheck`, `npm run test`, `npm run build`
   - The build needs env vars that `next build` reads at build time, and `next typegen` loads `next.config.ts` too. Use dummy values from GitHub secrets or inline placeholders. No real database or vendor secret is needed for the build; if a page reads the database at build time, the plan review records that. The workflow lists every variable and says which are dummies
3. **Production migrations** as their own step that runs before the production deploy:
   - Option A: a GitHub Actions job on `push` to `main` with `concurrency: production-migrate` that runs `npm run db:migrate:deploy` with a `PRODUCTION_DIRECT_URL` secret, then triggers the production deploy through a Vercel deploy hook. Git auto-deploy of `main` is turned off for this (check the current Vercel setting, e.g. `git.deploymentEnabled` in `vercel.json`); an "Ignored Build Step" can only skip a build, it cannot wait for the migration
   - Option B: Vercel's Build Command becomes `npm run vercel-build` = `node scripts/migrate-if-allowed.mjs && npm run build`; the script migrates only when `VERCEL_ENV` is `production` or `preview` and the target is that environment's own database
   - **In both options, Preview builds run `prisma migrate deploy` against their own Neon branch**, never against production
   - The plan review picks one and records it in an ADR ("How schema changes reach production"), including expand/contract for breaking changes (the deprecated `User` Stripe columns are the example)
4. **Preview databases:** every Vercel preview uses a Neon branch, never production. Either the Neon Vercel integration (a branch per preview; it injects `DATABASE_URL` and `DATABASE_URL_UNPOOLED`, so map `DIRECT_URL` to `DATABASE_URL_UNPOOLED` for Prisma), or one shared `development` branch for all previews as the simple start
5. **Dependabot** `.github/dependabot.yml` for npm (weekly, grouped minor/patch) and GitHub Actions
6. **Branch protection** on `main` (done in GitHub settings, not code): CI must pass before merge. Write the steps in the README

## Non-goals

E2E in CI (feature 5), integration tests against Postgres (feature 4), deployment outside Vercel.

## Acceptance criteria

- A PR shows a green or red CI check; a lint error, a type error or a failing test turns it red
- `npm run build` no longer touches any database
- A preview deployment cannot reach the production database (verified by reading the Vercel env settings and the build log of one preview)
- Production migrations run once per merge, before the new code serves traffic, and are written down in the ADR
- `README.md` "Scripts" and the CLAUDE.md commands list include `typecheck` and the migrate script; every README line that says the build migrates (the one about `DATABASE_URL` and the one saying "the build applies pending migrations") is corrected

## Tests

No unit tests. Proof is a PR with a deliberately failing test (red CI), then fixed (green), and the build log of a preview.
