# 21. Full E2E suite

## Why

- Feature 22 (CSP and Cache Components) changes the headers and how every route renders and caches. Before that, the main user journeys must be covered end to end.
- The smoke suite (feature 5) and the journeys each feature since has written cover single flows. What is still missing: accessibility checks of whole pages, visual baselines, and the journeys no feature owned.
- Interview angle: "How do you decide what goes into E2E vs unit tests?", "How do you keep E2E tests from being flaky?", "Visual regression: when is it worth it?"

## Prerequisite

Features 15–20 merged: every UI change lands before the baselines. Each of those features wrote its own journeys (the rule "run `test:e2e` when a page or route changed"); this feature does not collect them.

## Scope

1. **Journeys not owned by an earlier feature** (extend `e2e/`; fresh users from the test seed, never the demo users):
   - Free plan: a fresh Free user seeded with 49 items creates the 50th, the 51st is refused with the upgrade message
   - Pro (a Pro user from the test seed, with a `Subscription` row): upload an image, see it in the gallery; a file item's download link works. Uploads need test R2 credentials in CI and R2 CORS for the CI origin; the plan decides between that and mocking the presign step
   - favorites and pins: optimistic star, survives reload; failure path by intercepting the action response with a 500 (rollback visible)
   - **the star across the save, commit by commit**: `useItemFavorites` updates after an await inside `startTransition(() => onSaved(...))`, or the star falls back for a moment. A final-state assertion passes with or without the bug, so the test observes every change of the star's `aria-pressed` (a `MutationObserver` in the page) and asserts it never falls back
   - URL filters and sort (feature 7), search (feature 8), infinite favorites (feature 12), import → export round trip (feature 10), language switch to German and back (feature 11)
   - sign out, protected route redirects to sign-in
   - **change the password**: `ChangePasswordForm` signs the user out through a Server Action that redirects. A seeded user of its own (a password change revokes every session of its user): one more of the extra users derived from the run's email (`listsUserEmail` in `scripts/e2e-user.ts`, its session saved by `e2e/auth.setup.ts`), with its line in the README section on end-to-end tests. Reset and confirm-email need a token from an email and stay covered by the component tests
2. **Accessibility**: `@axe-core/playwright` on the main pages; no serious or critical violations
3. **Visual regression**: `toHaveScreenshot` on about six pages (dashboard, type list, drawer, palette, settings, marketing), Linux in CI only, masks for dates. The consent of feature 20 is set before every screenshot and journey, or the banner is in every baseline
4. **Its own Upstash database**: the e2e tests use the app's `devstash-ratelimit` today (the free plan allows one database), and its token sits in the GitHub secrets under Actions and Dependabot. Either a dedicated database (needs the user's second account or a paid plan: new values for the two `E2E_UPSTASH_*` secrets and `.env.test`, no code), or a local Redis with a REST proxy in Docker and in the `e2e` job (no secret, would run on fork PRs; check it against the Lua scripts of `@upstash/ratelimit`). The plan asks the user for the account only if the dedicated database is chosen
5. **Stability**: no fixed waits; each test creates its own data; three green runs in a row, and `--repeat-each` under the Free limit
6. **Where it runs**: the production build in CI (as in feature 5) or the Vercel preview URL with its database; record the choice
7. Optionally Firefox and WebKit for the smoke journeys

## Non-goals

Load testing, testing Stripe's hosted pages, OpenAI output quality (the AI route is mocked or a fixed fake).

## Acceptance criteria

- All journeys green in CI three runs in a row
- axe reports no serious or critical issues on the covered pages
- Screenshot baselines committed; a deliberate style change shows a readable diff
- The e2e job no longer uses the app's Upstash database
