# 16. Cache Components

## Why

- Nothing is cached today. `src/app/(app)/layout.tsx` sets `export const dynamic = "force-dynamic"` (redundant, because reading the session cookie already makes the routes dynamic), and every mutation calls `refresh()`. That is consistent, but it was never decided in an ADR.
- Next.js 16.4 recommends Cache Components (with Partial Prefetching) for every app, enables it for new apps, and announces it as the default in Next.js 17. `force-dynamic` is not allowed with it.
- Item types and the marketing page are the same for every user and are rendered on every request.
- Interview angle: the most asked Next.js topic. "What is cached in your app and why?", "`updateTag` vs `revalidateTag` vs `refresh`", "What is Partial Prerendering / a static shell?"

## Prerequisite

Feature 15 green: this change touches every route.

## Scope

1. **ADR "Caching strategy"** first: what is cached (system item types, entitlements per user with a tag, marketing page, legal pages), what stays per request (everything else), and the invalidation matrix per Server Action
2. Enable `cacheComponents` and `partialPrefetching` in `next.config.ts` (names and behaviour checked in the installed docs); remove `force-dynamic`
3. Fix what the build reports: dynamic reads (`cookies()`, session) inside `<Suspense>` boundaries so routes get a static shell plus streamed per-user parts
4. `'use cache'` with `cacheLife` and `cacheTag` on the chosen reads; per-user data takes `userId` (and the locale from feature 11) as arguments so cache keys separate users
5. Invalidation: in Server Actions, `updateTag` where the user must see their own change at once, `revalidateTag` where eventual is fine, `refresh()` where no cached data changed. **`updateTag` works only in Server Actions**: the Stripe webhook (a Route Handler) changes entitlements, so it uses `revalidateTag`. Document each in the ADR's invalidation matrix
6. `export const ensureStatic = "navigation"` on the marketing pages (`/`, `/de`) and the legal pages, which never read the locale cookie (cross-file decision 1)
7. **`<Activity>` side effect**: Next keeps recently visited routes hidden but mounted; check `useUnsavedChanges`, dialogs and effects behave (React docs: effects are cleaned up while hidden)
8. Use `next upgrade --agent` or the documented migration guide as a checklist, not as an autopilot
9. Measure before and after (TTFB, LCP on the dashboard; number of database queries per page) and document in `docs/performance.md`

## Non-goals

A remote cache handler (Redis), caching AI responses, caching file URLs.

## Acceptance criteria

- `next build` passes with Cache Components on; the build output shows which routes have a static shell
- A user never sees another user's cached data (feature 4 matrix + an E2E with two users); no `'use cache'` function calls `getSessionUser`, `auth()` or `cookies()` — `userId` and `locale` come in as arguments
- After every mutation the user sees the change (feature 15 suite green)
- Before/after numbers documented

## Tests

Full E2E suite, integration matrix, plus a test that two users get different cached entitlements.
