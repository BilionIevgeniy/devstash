# 13. Performance and SEO

## Why

- Nothing is measured: no bundle baseline, no Web Vitals. Changes are guesses.
- `CreateItemDialog` (`features/items/components/CreateItemDialog.tsx`) is imported statically by the top bar of every app page, so the whole create form (fields, editor wrapper, upload, collection select, AI parts) ships with every page.
- Sidebar navigation shows nothing until the target segment's `loading.tsx` appears.
- The public marketing page has no metadata beyond the root layout, no sitemap, no robots file and no Open Graph image.
- Interview angle: "How do you find out why a page is slow?", "What is code splitting in Next.js?", "Core Web Vitals: what is INP?", "How does the Metadata API work?"

## Scope

### Measure first

1. Bundle analysis: `next analyze --output --snapshot baseline` (Turbopack analyzer; check the flags in the installed docs); save the baseline numbers in `docs/performance.md`
2. Web Vitals: `useReportWebVitals` sends LCP, INP and CLS to a small route handler that logs them through `lib/logger.ts` (feature 6), plus the console in development. Vercel Speed Insights instead only if accepted as a processor (then update the privacy notice)

### Fix what the measurement confirms

3. Load the body of `CreateItemDialog` (imported by `NewItemButton`, `items/[type]/page.tsx` and `CreateMenu`) and of the collection create/edit dialogs with `next/dynamic` when it opens; preload on hover/focus of the trigger
4. `useLinkStatus` in sidebar links: a small pending indicator while navigating
5. Images in `ItemBody`/`ImageCard`: explicit size or aspect ratio so nothing shifts (they stay `<img>` because of short-lived signed URLs, as the code comment explains)
6. Compare after each fix and write the numbers in the PR

### SEO for the public pages

7. `metadata` / `generateMetadata` for the marketing page and legal pages (title, description, canonical)
8. `app/sitemap.ts` (public pages only) and `app/robots.ts` (disallow the app routes)
9. Open Graph image for the marketing page (`opengraph-image.tsx` with `ImageResponse`, or a static image)
10. App routes get `robots: noindex`

## Non-goals

Server-side caching (feature 16), a CDN for user files, changing the design.

## Acceptance criteria

- Baseline and after numbers documented; the shared JavaScript of app pages is smaller after the dialog split
- With the preload warmed by hover/focus, the create dialog is interactive less than 200 ms after the click
- `/sitemap.xml`, `/robots.txt` and the OG image respond; app routes are `noindex`
- No CLS from item images

## Tests

E2E (feature 15): sitemap and robots respond; create dialog still opens and saves. Manual Lighthouse run documented.
