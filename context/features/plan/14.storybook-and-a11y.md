# 14. Storybook and accessibility

## Why

- There is no place to see every UI state of a component (loading, empty, error, Pro-locked) without clicking through the app with the right data.
- Accessibility is checked by hand only. WCAG 2.1 AA is the target the BFSG refers to (DevStash is exempt as a micro-project, but it is the standard German companies work to).
- Interview angle: "Why Storybook?", "How do you test accessibility automatically?", "Component in isolation vs in the app: what does each catch?"

## Scope (kept small on purpose)

1. **Storybook 10** with the **`@storybook/nextjs-vite`** framework (required for the Vitest addon on Next.js); pin versions and check them against Next 16.4 and React 19. **Before installing, confirm that `@storybook/addon-vitest`'s peer range covers the installed `vitest@5`**; if it does not, stop and report instead of downgrading Vitest
2. Global decorators: dark theme (the app default), the next-intl provider (feature 11), Tailwind styles from `globals.css`
3. **Stories** for:
   - `components/ui`: button, badge, input, dropdown menu, sheet (variants via controls)
   - about six product components: `ItemCard`/`ItemRow`, `CollectionCard`, `PaletteResults` (loading, error, results, empty), `EditorFallback`, `PricingCard`, one form field
   - Server Actions and `next/navigation` mocked through module mocks; stories target client and presentational components (async Server Components are not supported as stories)
4. **Tests from stories**: `@storybook/addon-vitest` runs stories as tests (Vitest Browser Mode under the hood) as a third Vitest project `storybook` next to `unit` and `dom`; it shares the Playwright browser install with the E2E CI job. `play` functions for 2–3 interactions (open menu, select, submit)
5. **Accessibility**: `@storybook/addon-a11y` with violations failing the test run (`a11y: { test: "error" }`); fix what it finds
6. CI: build Storybook and run the story tests in the existing workflow

## Non-goals

Stories for every component, publishing Storybook (Chromatic or a static deploy), visual regression (feature 15 uses Playwright screenshots), a design-system package.

## Acceptance criteria

- `npm run storybook` and `npm run build-storybook` work
- Story tests and a11y checks run in CI and are green
- Every listed component has its main states as stories
