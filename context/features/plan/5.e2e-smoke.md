# 5. E2E smoke tests

## Why

- Pages are async Server Components. The Next.js docs say Vitest cannot render them, so only an end-to-end test proves that sign-in, the item list and the drawer work together.
- Features 7, 11, 12 and 16 touch every route. A small E2E suite is the safety net before those refactors.
- Interview angle: "What do your E2E tests cover, and why only that?", "How do you keep E2E tests stable?"

## Scope

1. **Playwright** (`@playwright/test`, pinned), `playwright.config.ts`, tests in `e2e/`
2. **Against the production build**: `webServer` runs `npm run build && npm run start` (not `next dev`), with the test database from feature 4
3. **Environment**: `next start` needs real values for `AUTH_SECRET` (any test secret), `APP_URL=http://localhost:3000` (the app throws in production without it) and Upstash (sign-in is rate-limited and fails closed: use a dedicated test Upstash database via secrets). Everything else gets dummies; the spec of the workflow lists each variable
4. **Fresh user per run**: a setup project creates a new, already verified user with the test seed of feature 4 (sign-in through the UI would otherwise wait for the verification email) and signs in through the sign-in page, then saves `storageState`; the tests reuse it. The demo users are not used (the Free demo user has 49 of 50 items, so a second run would hit the limit)
5. **Smoke journeys** (Chromium only for now):
   - sign in with email and password, land on the dashboard
   - create a snippet, see it in `/items/snippets`
   - open it in the drawer (intercepting route), close with Esc, focus returns to the card
   - the marketing footer links to `/impressum` and `/datenschutz` (feature 2)
6. **Selectors** by role and label only (`getByRole`, `getByLabel`), no CSS classes
7. **CI job** `e2e` after `ci` passes: install browsers, run, upload the HTML report and traces on failure
8. `npm run test:e2e` script

## Non-goals

Full coverage (feature 15), visual tests, other browsers, running against Vercel previews (feature 15 decides).

## Acceptance criteria

- `npm run test:e2e` is green locally and in CI
- A broken journey (for example a renamed button) fails with a trace that shows where
- Runtime under ~3 minutes in CI
