# 15. Full E2E suite

## Why

- Feature 16 (Cache Components) changes how every route renders and caches. Before that, the main user journeys must be covered end to end.
- The smoke suite (feature 5) covers four journeys. The product has more that only a browser can check: plan limits, upgrade, file upload, AI, import/export, language switch.
- Interview angle: "How do you decide what goes into E2E vs unit tests?", "How do you keep E2E tests from being flaky?", "Visual regression: when is it worth it?"

## Scope

1. **Journeys** (extend `e2e/` from feature 5; every journey uses fresh users from the test seed of feature 4, never the demo users):
   - Free plan: a fresh Free user seeded with 49 items creates the 50th, the 51st is refused with the upgrade message
   - Pro (a Pro user from the test seed, with a `Subscription` row): upload an image, see it in the gallery; file item download link works. Uploads need test R2 credentials in CI and R2 CORS allowing the CI origin; the plan decides between that and mocking the presign step
   - favorites and pins: optimistic star, survives reload; failure path by intercepting the action response with a 500 (rollback visible)
   - URL filters and sort (feature 7), search (feature 8), infinite favorites (feature 12)
   - import → export round trip (feature 10)
   - language switch to German and back (feature 11)
   - sign out, protected route redirects to sign-in
   - Stripe: upgrade flow in test mode up to the Stripe page (do not automate Stripe's own page)
2. **Accessibility**: `@axe-core/playwright` on the main pages; no serious or critical violations
3. **Visual regression**: `toHaveScreenshot` on ~6 pages (dashboard, type list, drawer, palette, settings, marketing), Linux in CI only, masks for dates
4. **Stability**: test ids only where no role or label exists; no fixed waits; each test creates its own data and cleans up
5. **Where it runs**: decide in the plan between the production build in CI (as in feature 5) and the Vercel preview URL with its Neon branch (feature 1); record the choice
6. Optionally Firefox and WebKit for the smoke journeys

## Non-goals

Load testing, testing Stripe's hosted pages, OpenAI output quality (mock the AI route in E2E or use a fixed fake).

## Acceptance criteria

- All journeys green in CI three runs in a row (no flakes)
- axe reports no serious/critical issues on the covered pages
- Screenshot baselines committed; a deliberate style change shows a readable diff
