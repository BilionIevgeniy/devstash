## 5. Cookies and device storage (§ 25 TDDDG)

Read from `@auth/core` (`lib/utils/cookie.js`), the app code and the sidebar code on 2026-11-11. ⟦OPERATOR: confirm the set in DevTools → Application → Cookies on the production host after a GitHub sign-in, and look at Local Storage there too⟧.

In production over HTTPS the Auth.js names carry a prefix (`__Secure-`, and `__Host-` for the CSRF token).

| Cookie                      | Purpose                                       | Lifetime                                                                               | Why no consent is needed                                                                                                                                                                    |
| --------------------------- | --------------------------------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `authjs.session-token`      | The session (JWT, encrypted and signed)       | Auth.js default: 30 days since the last activity, renewed whenever the session is read | Strictly necessary for the sign-in the user asked for (§ 25 (2) Nr. 2)                                                                                                                      |
| `authjs.csrf-token`         | Protects the sign-in forms against forgery    | Session                                                                                | Strictly necessary security cookie of the sign-in the site offers. Set on the first page view, see below                                                                                    |
| `authjs.callback-url`       | Where to return after sign-in                 | Session                                                                                | Same position, but weaker for a visitor who never signs in ⟦OPERATOR: take this position knowingly⟧. Set on the first page view, see below                                                  |
| `authjs.pkce.code_verifier` | The GitHub sign-in handshake                  | 15 minutes                                                                             | Strictly necessary, set only when signing in with GitHub. `authjs.state` appears only if a `redirectProxyUrl` is configured, `authjs.nonce` only for OpenID providers; neither is set today |
| `sidebar-open`              | Remembers whether the desktop sidebar is open | 1 year                                                                                 | Set only when the user toggles the sidebar, so it serves a setting they asked for; first-party, no identifier                                                                               |

**When they are set.** Auth.js creates `csrf-token` and `callback-url` on any request to `/api/auth/*`, including a session read with no session. The marketing header calls `GET /api/auth/session` on every page of the group (`useHasSession`), so an anonymous visitor gets both on the first page view, the legal pages included.

**Where the lifetimes come from.** The session lifetime is the Auth.js default (`session.maxAge` is not set in `auth.ts`), and `sidebar-open` takes its name and one year from `SIDEBAR_COOKIE` and `YEAR_SECONDS` in `src/features/app-shell/domain/sidebar.ts`. A change in either is a change of this table and of the notice.

No `localStorage`, `sessionStorage` or IndexedDB in `src/`. No analytics, advertising or tracking cookie. **A consent banner is therefore not needed.** Any future analytics, Sentry Replay or embedded third-party content changes this.

## 6. Technical and organisational measures (summary)

- HTTPS everywhere; HSTS in production; security headers (`frame-ancestors 'none'`, `nosniff`, referrer policy)
- Passwords hashed with bcrypt; sessions are encrypted and signed `httpOnly` JWT cookies; new GitHub sign-ins store no GitHub token (an `Account` row from before 2026-11-06 may still hold one: `context/todo.md`, "Auth")
- Reads and writes are scoped by the signed-in user's id; the exceptions are the lookups before sign-in by email or token and the Stripe sync, scoped by customer ([ADR 0012](../adr/0012-webhook-writes-scoped-by-customer.md)). Entitlements come from the database
- Rate limits on sign-in, registration and email sending, and on every AI function, with hashed identifiers; the limiter fails closed
- Private R2 bucket; files are read through short-lived signed URLs; the browser uploads straight to R2
- AI calls use `store: false` and a hashed `safety_identifier`
- Deleting the account cancels the Stripe subscription, deletes the Stripe customer, purges the user's files and deletes the rows
- Outside the app after a deletion: Resend's copies of sent emails, the records Stripe must keep by law, and the app's authorization in the user's GitHub account, which the user can revoke in GitHub's settings

## 7. Rights of the data subject

Access, rectification (by email: the profile page is read-only, and the user changes the password and deletes the account in the application), erasure (self-service "Delete account" in the settings), restriction, objection to processing based on legitimate interest, and a complaint to the supervisory authority. Export of the data as a file is planned (feature 10) and is not promised in the notice until it exists. Requests go to the controller's email address.
